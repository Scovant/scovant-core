# Readiness R2

`scovant_core.r2` is the open, bounded readiness model behind the
**Technical Readiness Rating**.

Since 0.17.0 `scovant scan` reports **Technical Readiness** in `readiness.technical` (rating, grade, badge, status, coverage, model id, evidence state `ESTIMATED`, scope `CORE_PASSIVE`, site type, per-category ratings and the rules Core could not measure), plus `technical_outcomes` (per-rule state, reason and scope; the shape is in [`report.schema.json`](report.schema.json)). Same method as Scovant Cloud, Core's own evidence: Core samples fewer pages, never performs an MCP handshake and counts tokens only with the `[tokens]` extra, so required, weighted rules Core could not measure are listed in `not_measured` with a reason (`probe_failed:<probe>`, `not_gathered_by_core`, `handshake_not_performed`, `tokenizer_unavailable`, `no_pages_evaluated`, `bot_protection_blocked`, `probe_failed:pages`) and lower coverage — never a FAIL. The Static Signal Score is unchanged in this release.

## Site type

The site type decides which rules apply (`ucp` needs booking, commerce, restaurant or saas; `citability` needs a content type; commerce-gated rules need a commerce profile).

| Core profile | R2 site type |
|---|---|
| `commerce` | `commerce` |
| `saas` | `saas` |
| `api` | `saas` |
| `content` | `other` (a content type: citability applies) |
| no profile / low confidence | `unknown` (commerce-gated rules N/A, as Cloud) |

`--site-type <type>` overrides detection (any R2 site type). `site_type_origin` in the report records `detected`, `flag` or `unknown`.

## Outcomes

Every rule produces one outcome per scan:

| State | Meaning | Score | Coverage |
|---|---|---|---|
| `PASS` / `WARN` / `FAIL` | measured | value 1 / 0.5 / 0 | measured |
| `N/A` | the rule does not apply to this site profile | excluded | excluded |
| `NOT_MEASURED` | the input the rule needs was not available | excluded | lowers |
| `ERROR` | the scanner failed | excluded | lowers; the result is `DEGRADED` |
| `BLOCKED_BY_POLICY` | the site refused the scanner's identity | excluded | lowers |
| `UNKNOWN` | the rule produced no outcome | excluded | lowers |

Missing evidence is never counted as a failure: it lowers coverage, and
only a measured WARN or FAIL counts against a category. (A category's score
can still move when a measured PASS becomes unmeasured, because the PASS no
longer counts toward it.)

### Walled pages and probe failures

A document answered with status 429 or 5xx (or a truncated robots.txt) is
`NOT_MEASURED`, never read as allow-all or absent; a 404 is a real answer. A
page whose scored content was itself a bot-protection wall is not measured
for Technical Readiness (`bot_protection_blocked` when every page is
walled); a rule that is N/A on every clean page stays N/A. This skip applies to
Technical Readiness only; a host's other readiness views may still evaluate
those pages. `PAGE_TOKEN_BLOAT` needs the optional `scovant-core[tokens]` extra
and is `NOT_MEASURED` (`tokenizer_unavailable`) without it.

### What a Technical scan gathers

Technical Readiness gathers, beyond the Static Signal Score documents:
markdown-for-agents negotiation, homepage `Link` headers, agent payment
probes (x402, L402, ACP, MPP), the machine-representation probe, per-page
content blocks and landmark tags, and a crawl graph over the gathered pages
(rooted at the scan's final URL). A 429/5xx answer to the homepage request of the
markdown, `Link`-header and machine-representation probes, to any agent-payments
probe when nothing was found, or a probe that raised, is `NOT_MEASURED`
(`probe_failed:<probe>`), never read as absent. (A failed `/index.md` mirror
request still reads as no mirror, and agent discovery keeps its existing
semantics.) `technical=False` gathers none of them. On the eight golden sites
every counted Technical rule is measured or N/A except
`MCP_DISCOVERY_INVALID` where an MCP endpoint is declared: Core never
performs the MCP handshake, so that rule is the one remaining
not-measured gap.

## Formula

```
value      = 1 − f × (1 − v)      v: PASS 1, WARN 0.5, FAIL 0
                                   f: failed/measured pages for a page rule, 1 for a domain rule
category   = 100 × (Σ w·value + P) / (Σ w + P)  over measured, weighted rules
overall    = Σ category × W / Σ W             over categories that have a score
rating     = overall rounded half-up, then gates
coverage   = Σ w measured / Σ w applicable      (weighted and gate rules; merged members once)
rating     is clamped to 0..100
```

`P` is the policy's `category_prior_weight` (the public policy uses 14, one
medium-severity rule): a pseudo-pass weight added to every category
that has at least one measured rule, so a single failure in a category with few
rules cannot drive it to 0. It is not evidence: coverage ignores it, and a
category with nothing measured still has no score.

Rule weight `w` comes from its severity: critical 40, high 25, medium 14,
low 6, info 2. Category weights `W`: discoverability 0.17, structured 0.18,
consistency 0.15, actionability 0.12, trust 0.08, ucp 0.12, citability 0.18.
`ucp` applies to booking, commerce, restaurant and saas sites; `citability`
to blog, docs, documentation, media, news, other and portfolio sites.

## Status, grade, badge

- coverage below 0.60, or no category with a score → `INSUFFICIENT_EVIDENCE`, no rating;
- coverage below 0.85, or any `ERROR` → `DEGRADED`, rating without grade or badge;
- otherwise `OK`: grade A ≥ 90, B ≥ 80, C ≥ 60, else D; badge `agent_ready` ≥ 80, `agent_compatible` ≥ 60.

## Gates and root causes

A rule is `weighted` (in its category), `gate` (never in a category; a
`FAIL` fires the gate for its root-cause group) or `diagnostic` (explained,
never counted). A gate never removes a weighted outcome from the rating. The
public gate `agent_access_blocked` withholds the badge and leaves the number
alone; a host policy may instead cap the rating.

Weighted outcomes that share a root-cause group, a scope and the same
evidence count as ONE element: it has the weight of the heaviest member and
the value of the worst member (PASS, WARN and FAIL members alike). A
root-cause group always stays inside one category. Outcomes with different
evidence are never merged. Fixing any member can therefore only raise the
rating.

Coverage counts weighted and gate outcomes; merged members count once.

## Versions

A result names its model as `<formula>@<digest>` — currently `R2.1@…` (R2.1
added the category prior). The digest covers the formula version, every rule
definition and every policy value, so any change to a weight, threshold or
rule produces a new model id. Results from different
model ids are not comparable as a change in the site.
